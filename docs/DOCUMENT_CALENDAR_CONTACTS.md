# Document, calendar and contact workflow

Workspace lists now offer Back, preserve browser history, and retain existing detail/form return controls. A deep link without local navigation returns to the dashboard. Change Orders is absent from the sidebar and mobile More menu; the legacy route remains for existing approval links.

Open an active invoice or estimate and choose Change order. This works on drafts and before a job exists. Customer, source document, original scope/prices, service address and work status are loaded from the database; new charges are entered separately so the original work is never billed twice. The server clamps source references, locks scheduling against completion, blocks completed/canceled work, and makes retries idempotent. Change orders retain an invoice/estimate reference even before scheduling.

Calendar dates open an Event/Reminder form in the business timezone. It supports notes, a team member, start/end, conflicts and safe retries. Standalone events can be reopened from the calendar. The duplicate date/month input is removed; week/month toggles, date cells and period arrows remain. Activated AI access can open the existing Finviant assistant with the selected date and timezone prefilled for review. Existing provider configuration, entitlements, quotas and confirmation rules apply; this change does not create API credentials or certify live model output.

New invoice/estimate forms accept typed customer names and optional email/phone. Saved customers remain optional. A new customer and the document save in one transaction; a failed document rolls back the new customer. Payment methods/instructions are selected in those forms and during initial business setup, replacing the standalone Payment options settings button. Quotes retain their choices when converted or completed into invoices. Issued payment details stay frozen, and staff cannot substitute payment destinations.

The primary owner can import selected phone contacts through a supported browser picker or a .vcf export. iPhone instructions use Contacts → Lists → hold the primary-account list → Export → Files. The browser previews names, email and phone before upload; other card fields/photos/notes are ignored. Unselected contacts are not sent. Imports use batches of 100, skip existing email/phone matches without overwriting records, verify retries, and preserve existing plan/storage limits. File limits: 8 MB and 2,000 cards. Browser picker access is on demand; continuous phone contact synchronization is not implemented.

Sources: https://developer.chrome.com/docs/capabilities/web-apis/contact-picker and https://support.apple.com/guide/iphone/export-contacts-iph075ddebf2/ios . Physical phone contact export/picker and live OpenAI validation remain separate from synthetic browser checks. Preserve the existing private staging database and Vercel protection when deploying.
