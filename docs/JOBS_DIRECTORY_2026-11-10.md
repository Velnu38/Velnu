# Jobs directory pagination

Jobs List and Board request 25 records per page from a checked business-scoped RPC. Timing/crew/customer filters and literal title/status/customer search run on the server. Filter counts describe the complete filtered workspace, independent of the text search. Ordering uses the existing past-appointment priority, scheduled time and a stable ID tie-breaker. Out-of-range pages clamp after concurrent record changes. The existing Overview and Job Management workspaces retain their behavior; their full-list reads remain capacity work.

The client rejects malformed page responses, ignores stale requests and keeps the search field mounted while loading. Search is debounced by 200 ms. Existing deep links still fetch the requested job directly. Customer metadata is cached for page/search changes within the same workspace and access scope; explicit refresh reloads it. No permissions, seats or worker accounts change.

Local evidence: 50,002 synthetic jobs cross the former 50,000-row list boundary; 25-row first page, two-row last page, full counts, literal percent searches, worker filtering, out-of-range clamps, invalid input, unrelated and anonymous denial, and jobs-only billing redaction pass in PGlite on Node 22.23.4. Existing Jobs board/Overview/plan DOM journeys, build and startup guards pass. Full PostgreSQL migration replay includes a genuine authenticated directory request and foreign/anonymous denial. Browser coverage includes 390/1440 widths, successive pages, search focus during delayed reads and failure recovery. Final CI execution is required before deployment.

Deployment: apply only the new jobs_directory_pagination migration to the existing beta after complete CI. Verify the function and grants, then deploy the compatible frontend. Roll back to the prior frontend; the additive read-only RPC can remain. The review branch cannot deploy automatically. This does not establish hundreds-of-business capacity or close PERF-01/PERF-02; representative query plans, the rest of the unbounded views and the isolated 60-minute workload remain open.
