# Document conveniences

The existing invoice, estimate and change-order editors retain saved single services and now offer Service packages. A package saves 1–50 complete lines with their quantities, prices and tax rates. Adding one copies its values into the editable draft for review. It preserves existing partial lines, rejects overflow without removing work and never edits another document. Names are unique among active packages in a business. Removing a saved package archives it; billing write access is required to save or archive. Read access follows the existing billing module rules. Manual entry continues if loading fails.

Invoices and estimates gain an optional Customer PO / reference, limited to 120 characters on one line. It is part of the existing atomic save and request fingerprint, draft optimistic concurrency, customer snapshot and shared PDF renderer. Job invoice creation accepts it; linked estimate/deposit/job invoices inherit their source estimate reference when none was specified. Generic Copy to new draft resets the reference along with existing transactional reset rules. An issued reference cannot be changed, even by a direct row update. Historical snapshots without a reference do not gain an extra null key or change their content hash. Issued PDF bytes remain in their existing immutable revisions.

Validation includes PostgreSQL package authorization/validation, document create/edit/retry and conversion, rejected issued-reference changes, local PDF text extraction and rendered visual inspection, package DOM loading/double-click/overflow/archive behavior, and complete replay assertions against the final application schema. Local checks do not replace hosted tenant or physical-device acceptance.

No new subscription, Fin request, payment, charge or customer send is required by these conveniences.
